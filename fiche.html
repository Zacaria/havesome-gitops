FICHE MÉMO / GITOPS

Du commit
au réel.

Une intention versionnée, un agent qui observe, une boucle qui tente de rapprocher le réel du désiré.

La boucle

01 / Git
État désiré, proposé et revu.

02 / Contrôleur
Récupère, compare et réconcilie selon sa configuration.

03 / Cluster
État observé et santé des charges.

Une ressource synchronisée n'est pas forcément saine. Une correction manuelle peut être annulée par le contrôleur : reportez l'intention durable dans Git.

Quatre principes

Déclaratif

Décrire l'état voulu.

Versionné et immuable

Conserver les versions et leur historique.

Récupéré automatiquement

Un agent tire l'intention depuis la source.

Réconcilié en continu

Il observe et tente de réduire l'écart.

Principes OpenGitOps ↗

Premiers réflexes

Ces commandes consultent la configuration locale ou les ressources. Installez les CLI et vérifiez vos droits de lecture. Avant toute requête au cluster, contrôlez le contexte ; adaptez catalogue et production à votre environnement. Les résultats peuvent contenir des informations sensibles.

Vérifier le contexte Kubernetes

kubectl config current-context
Référence kubectl ↗

Observer les pods d'un namespace

kubectl get pods -n production
Référence kubectl get ↗

Inspecter une application Argo CD

Connexion Argo CD configurée ; remplacez le nom par celui de votre application.

argocd app get catalogue
Référence Argo CD ↗

Voir les Kustomizations Flux

Flux installé ; la commande utilise le namespace flux-system.

flux get kustomizations -n flux-system
Référence Flux ↗

Garder le contrôle

  • Protégez les branches et limitez les droits du contrôleur.
  • Ne commitez pas de secrets en clair : base64 n'est pas du chiffrement.
  • Évitez que plusieurs outils gèrent les mêmes champs.
  • Pour revenir en arrière, proposez une intention connue dans Git ; vérifiez aussi la compatibilité des données et migrations.
